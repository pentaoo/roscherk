# AI Usage в проекте Sheji

Файл для GitHub Pages:

```text
https://pentaoo.github.io/roscherk/ai-usage.md
```

Этот документ описывает, как в проекте **Sheji** использовалась нейросеть: для проектирования интерфейса, переноса Figma-идей в код, архитектурной декомпозиции, генерации контента, документирования решений, улучшения UX и проверки качества.

Sheji - статический fashion e-commerce сайт на `HTML`, `CSS` и vanilla `JavaScript`. В проекте нет React, Next.js, сборщика или backend, но есть полноценные пользовательские сценарии: коллекции, каталог, фильтры, поиск, карточки товара, корзина, избранное, страницы показов, EN/RU локализация и скрытые мини-игры внутри раскрытых карточек коллекций.

```text
ai-usage.md
```

## Источники контекста для нейросети

В проекте создана отдельная папка `ai-context/`. Она работает как проектная память для AI-ассистентов и помогает не начинать каждую сессию с нуля.

Основные файлы:

- `ai-context/00-operating-rules.md` - правила, которые AI должен учитывать перед изменениями.
- `ai-context/project/overview.md` - краткое описание проекта и ограничений.
- `ai-context/project/AGENTS_Sheji.md` - подробная продуктовая и визуальная спецификация Sheji.
- `ai-context/design/figma-notes.md` - заметки по Figma-фреймам, размерам и визуальным решениям.
- `ai-context/design/tokens.md` - брендовые цвета, motion-токены и правила анимации.
- `ai-context/code/file-map.md` - карта HTML/CSS/JS файлов.
- `ai-context/code/conventions.md` - кодовые соглашения.
- `ai-context/decisions/decision-log.md` - журнал устойчивых решений.
- `ai-context/tasks/collection-mini-games.execPlan.md` - подробный план скрытых мини-игр.
- `ai-context/qa/checklist.md` - чеклист проверки перед завершением задач.
- `docs/sitemap.md` - карта сайта, пользовательские сценарии и известные ограничения.
- `docs/sitemap-visual.svg` - визуальная карта сайта.

Отдельные экспортированные диалоги с нейросетью в репозитории не найдены. Рядом с проектом был найден файл `../chat`, но он содержит только строку `fdagfd`, поэтому этот отчет основан на реальных артефактах проекта: структуре файлов, AI-контексте, документации и текущей реализации.

## Роль нейросети в проекте

Нейросеть использовалась не только как генератор кода. В Sheji она выполняла несколько ролей:

- продуктовый ассистент;
- помощник для design-to-code;
- архитектурный помощник для vanilla JS;
- автор проектной документации;
- помощник по UX и accessibility;
- инструмент планирования сложных фич;
- ревьюер ограничений и edge cases;
- помощник по визуальному polish интерфейса.

## Формирование концепции Sheji

AI помогал удерживать продуктовую идею Sheji:

- это не нейтральный fashion-магазин;
- это не стандартный Shopify-style storefront;
- интерфейс должен быть ярким, странным, коммерческим и немного провокационным;
- визуальная энергия ближе к MSCHF, чем к спокойному luxury;
- сайт должен оставаться настоящим магазином, но вести себя как арт-объект.

Эта концепция закреплена в `ai-context/project/AGENTS_Sheji.md`. Там же явно указано, что проект называется **Sheji**, а не NOSOK, и что нельзя переносить старые брендовые допущения из других проектов.

## Перенос Figma-идей в код

Нейросеть использовалась как помощник для перевода Figma-макетов в HTML/CSS/JS.

В `ai-context/design/figma-notes.md` зафиксированы заметки по hero refresh:

- Figma-фреймы `4700:7695` и `4700:7093`;
- белый холст;
- желтые collection cards слева;
- активная карточка `STONE` около `734x402`;
- соседние карточки со scale/rotation;
- зеленый square CTA;
- product collage справа;
- expanded collection hero с желтой левой панелью около `626px`;
- language switcher оставлен вне Figma-фреймов по продуктовому решению.

AI помогал не просто копировать внешний вид, а превращать дизайн в устойчивые компоненты: карточки, состояния, переходы, data-driven рендеринг и адаптивные ограничения.

## Проектная память вместо длинного промпта

Один из главных приемов - не держать знания только в чате.

Для проекта создана папка `ai-context/`, где хранятся:

- продуктовые правила;
- визуальная система;
- архитектура файлов;
- принятые решения;
- pending-задачи;
- QA-чеклист;
- ограничения на анимации;
- правила использования локальных SVG-иконок.

Это снижает риск, что следующая AI-сессия:

- случайно сменит стек на React или Next.js;
- добавит ненужные зависимости;
- сломает визуальный стиль;
- забудет Figma-источник;
- заменит Sheji чужим брендовым языком;
- начнет хаотично менять анимации.

## Архитектура vanilla JavaScript

Проект остался статическим, но AI помог разложить логику на поддерживаемые модули:

- `js/motion.js` - чтение CSS motion-токенов в JavaScript.
- `js/merchandising.js` - нормализация коллекций и товаров.
- `js/runtime.js` - общий runtime и события коллекций.
- `js/collections.js` - carousel коллекций и expanded state.
- `js/collage.js` - product collage активной коллекции.
- `js/catalogue.js` - каталог, фильтры, поиск, избранное и cart interactions.
- `js/product-detail.js` - карточка товара.
- `js/cart.js` - корзина и totals.
- `js/favorites.js` - избранное.
- `js/search-menu.js` - search overlay.
- `js/shows.js` - страницы и меню показов.
- `js/i18n.js` - локализация.
- `js/collection-games.js` - shell и state machine мини-игр.
- `js/collection-game-modules.js` - конкретные игровые модули.

Важный прием: вместо внедрения фреймворка был добавлен легкий runtime-слой. `ShejiRuntime` отправляет события:

```text
sheji:collectionchange
sheji:collectionnavigate
sheji:collectionselect
```

Так разные части сайта могут реагировать на выбор коллекции без жесткой связки между модулями.

## Нормализация данных

AI помог перейти от ручного связывания UI и данных к нормализованной модели.

В `js/merchandising.js` коллекции и товары получают:

- стабильные `id`;
- связь товара с коллекцией через `collectionId`;
- `searchableText` для поиска;
- `Map`-структуры для быстрых lookup-операций.

Это позволило сохранить простую статическую архитектуру `data/*.js`, но работать с данными более надежно.

## E-commerce без backend

Сайт работает на GitHub Pages, но имитирует полноценный магазин через клиентское состояние.

AI помог спроектировать:

- корзину;
- избранное;
- выбранный язык;
- фильтры каталога;
- поиск;
- счетчик корзины;
- переходы между каталогом, товаром и страницами показов.

Persistent-состояния хранятся в `localStorage`:

```text
sheji-cart
sheji-favorites
sheji-language
```

## Локализация EN/RU

AI помог добавить i18n-слой без внешней библиотеки.

В HTML используются атрибуты:

```text
data-i18n
data-i18n-aria-label
data-i18n-placeholder
```

`js/i18n.js` применяет переводы к:

- обычному тексту;
- `aria-label`;
- `placeholder`;
- `alt`;
- `title`.

Это важно, потому что в проекте много icon-only и hybrid controls, где доступность зависит не только от видимого текста.

## Скрытые мини-игры

Самый заметный AI-артефакт - `ai-context/tasks/collection-mini-games.execPlan.md`.

Идея: в раскрытой карточке коллекции есть designer face. Если быстро нажать на него несколько раз, открывается мини-игра коллекции.

Игры первых коллекций:

- Fruity - `Label Bird`;
- Stone - `Erosion Pong`;
- Water - `Drip Runner`;
- Bloom - `Petal Tennis`;
- Chrome - `Mirror Lane`.

AI помог описать мини-игры как controlled state machine:

```text
locked
arming
opening
active
paused
closing
ended
```

Заранее были зафиксированы требования:

- не разрушать expanded card;
- не терять состояние товаров и скролла;
- поддерживать клавиатуру;
- учитывать `prefers-reduced-motion`;
- чистить timers/listeners после выхода;
- держать активной только одну игру;
- возвращать фокус на designer face после закрытия;
- не превращать мини-игры в скидочную механику.

## Улучшение визуального стиля мини-игр

AI также использовался для визуального polish мини-игр.

Мини-игры были усилены под стиль сайта:

- толстые черные рамки;
- желтый фон;
- кислотные зеленые и розовые акценты;
- простые печатные labels;
- barcode/ruler-like паттерны;
- branded HUD;
- коллекционные stage labels;
- скрытие внешних floating controls на mobile во время активной игры.

При этом логика игр не усложнялась: упор был на визуальную систему сайта, а не на сложные фигуры или новые игровые механики.

## Motion-токены и дисциплина анимаций

В проекте отдельно зафиксировано правило: выразительные анимации нельзя менять случайно.

AI помог сформулировать подход:

- длительности лежат в CSS custom properties;
- JavaScript читает их через `ShejiMotion`;
- учитывается `prefers-reduced-motion`;
- open/close строится вокруг одной стабильной оболочки;
- внутренний контент раскрывается внутри shell;
- есть fallback cleanup, если `transitionend` не сработал.

Главный прием: **анимировать одну стабильную оболочку**. Это делает переходы обратимыми и снижает риск визуальных скачков.

## Локальные SVG-иконки

AI помог оформить правила для `source/icons/`.

В проекте хранится большой набор локальных Material SVG-иконок. Их имена должны совпадать с Figma/Material naming, чтобы дизайн и код использовали один словарь.

Правила:

- не переименовывать иконки без причины;
- декоративным иконкам ставить `alt=""`;
- icon-only controls должны иметь `aria-label`;
- если цвет должен управляться CSS, использовать inline SVG или `currentColor`.

В `ai-context/decisions/decision-log.md` сохранялись устойчивые решения:

- создать `ai-context/` как Markdown knowledge base;
- держать AI-контекст отдельно от `source/`;

Это помогает будущим AI-сессиям не спорить с уже принятыми решениями.

## Полезные AI-техники из проекта

### Контекстная папка

Вместо бесконечного промпта проект использует `ai-context/`. Это делает работу воспроизводимой.

### ExecPlan перед сложной фичей

Перед мини-играми был создан подробный план: цели, non-goals, state machine, accessibility, performance, cleanup и visual system.

### Non-goals

В плане явно указано, чего не делать:

- не создавать новые routes;
- не редизайнить collection cards;
- не переписывать expansion system;
- не добавлять скидки и аккаунты;
- не менять expressive animation без согласования.

### Event seam

`ShejiRuntime` стал тонким слоем событий между коллекциями, каталогом, collage и другими модулями.

### Accessibility в исходных требованиях

Доступность учитывалась не в конце, а в самих правилах и планах:

- `aria-label`;
- `alt=""`;
- keyboard focus;
- Escape behavior;
- focus return;
- reduced motion;
- inert/aria-hidden для скрытого контента.

## Ограничения AI-подхода

Нейросеть не является единственным источником истины.

В проекте важнее:

- текущий код;
- Figma-заметки;
- дизайн-токены;
- `ai-context/`;
- принятые решения;
- QA-чеклист.

AI не должен:

- менять стек без причины;
- добавлять зависимости без необходимости;
- перетирать пользовательские изменения;
- ломать визуальный язык Sheji;
- переписывать анимации без согласования;
- делать широкий рефакторинг вместо конкретной задачи.
